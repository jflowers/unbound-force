Testing uf_unleash_detect_resume (task 3.3 of unleash-deterministic-tools): the tool factory is createUnleashDetectResumeTool(exec, cwd, deps) with DetectResumeDependencies {readText, fileExists, readDir} — readDir returns bare file NAMES (string[]), and dispatch-artifact recency is ordered by the envelope's internal timestamp field (epoch-0 fallback, filename tie-break), NOT file mtime, so fakes serve artifact JSON through readText keyed on resolve(cwd, ".uf/artifacts/dispatch", name). GitExec contract for specs-mode ancestry: "merge-base --is-ancestor <sha> HEAD" exit 0 = ancestor-or-equal (return value), exit 1 = diverged (fake must throw Object.assign(new Error(...), { status: 1 }) — hasExitStatus checks .status), anything else = fail-closed RESUME_DETECT_ERROR; a plain new Error from the fake therefore simulates a genuine git failure. The specs dirty check runs "status --porcelain -- <featureDir>" (trailing slash accepted) and excludes ONLY featureDir+"tasks.md" by exact path equality after porcelainEntryPath parsing (slice(3), rename " -> " new path, quote strip) — untracked dirs collapse to "?? dir/" and count as DIRTY. Code-mode freshness is a pure string compare (head_sha === "rev-parse HEAD" result) — no merge-base call. Payload step keys are spec_review/code_review (underscore) but checkpoint-claim reconciliation checks the command's hyphenated completed_steps names "spec-review"/"code-review"; state I/O (readState + recordAutoCheckpoint) needs the vi.mock("node:fs") pattern from unleash-branch-gate.test.ts (lstatSync ENOENT default). The tool calls "rev-parse --abbrev-ref HEAD" twice (branch filter + resolveKey) and "rev-parse HEAD" once. Clarify marker probe — superseded 2026-10-19 by the clarification-marker-superset change: the substring includes("[NEEDS CLARIFICATION") prefix probe is deleted. That probe counted pluralized, unterminated, and bare marker-like text (including backticked prose references in completed specs, e.g. specs/018-unleash-command/spec.md) as markers and reported clarify not-done, but the colon-only scanner could not extract bare forms — an unsatisfiable wedge (blocked with no resolution path), not fail-safety. uf_unleash_detect_resume now derives marker presence from countClarificationMarkers(specText) > 0 over the single-sourced CLARIFICATION_MARKER_PATTERN — the same grammar scan_clarifications and resolve_clarification consume — so pluralized and unterminated marker-like text no longer holds clarify open, and bare markers extract as unscoped questions with a raw-marker-text fallback: every grammar-matched marker, however written, holds clarify open until resolved and surfaces in scan output with a visible resolution path. Well-formed marker syntax in backticked or fenced prose still counts (the grammar has no backtick or code-fence exclusion) and still reports clarify not-done — but as an extractable, resolvable question rather than an invisible hold.
