When an OpenSpec proposal.md explicitly identifies documentation artifacts that need updating (e.g., 'CHANGELOG.md entry for new tool and command file simplification'), the implementation workflow should treat those as tracked deliverables, not aspirational notes. The documentation gate in AGENTS.md requires assessment before marking tasks complete, but the proposal's own Impact section provides a more specific checklist. A prior review council flagging the same gap confirms this is a recurring pattern: documentation deliverables identified in proposals are systematically deferred past implementation. Consider adding a documentation task group to tasks.md that mirrors the proposal's Impact section.
