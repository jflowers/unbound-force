Website-side docs-gate issues filed from the meta-repo can be de-conditionalized at review time with Dewey's indexed website content: the filing session (Dewey MCP unavailable, search-first limited to the website repo's open gh issues) had to hedge its issue scope — "If the website documents the /uf.unleash pipeline..." — but the review session's Dewey full-text search over the website index confirmed the affected pages directly (content/docs/getting-started/product-owner, content/blog/unleash-in-practice, a demo deck), turning a hypothetical scope into a named-page checklist. Presence in the index is sufficient to make the issue concrete; absence is not conclusive (disk-website indexes lag), so re-verify at landing. Filing-time scope hedging under unavailable tooling is honest; review-time verification should close it and feed the page names back into the issue.
