When an OpenSpec spec delta makes evidence recording a SHALL obligation, pin the concrete artifact destination. 'Change record' is polysemous across this repo's changes: determinism-codification and router-pattern-codification titled CHANGELOG.md-entry requirements 'Change record'; router-pattern-codification's DE-004 evidence requirement pins 'a metrics artifact under the change directory, following the command-prose-pilot metrics.md precedent'; its AGENTS.md-layer-decision requirement means the change's own artifacts. seam-verification (2026-10) routed its DE-004 matrix, filed docs-issue number, and website-exemption rationale to an unpinned 'the change record' across proposal/design/tasks/spec delta while coordinating with landed #758 on DE-rule numbering and pack version — the coordination compared rule IDs and versions but not evidence-artifact conventions, so the new delta's scenario ('WHEN the change record is read') names no file a reviewer can open, and the merged determinism-policy spec would carry sibling DE-004 requirements with different or unspecified destinations. Same-capability coordination should compare where required evidence lands, not just rule IDs and pack versions, and every 'record X in the change record' task should name the concrete file that verifies it.
