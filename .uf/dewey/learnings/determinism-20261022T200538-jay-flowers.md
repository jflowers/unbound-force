Determinism classifications must derive from the nature of the work — whether a fixed repo procedure (skill or script) performs it end-to-end — never from routing metadata such as workflow tier or route type. Documentation authorship and code fixing are both judgment work (output varies with context; the determinism-first twice-test fails); classifying docs routes 'deterministic' because they are quick-tier 'docs' routes forces misleading skill directives or vacuous skill_absent_reason entries and pollutes the audit trail. Classification rubrics in specs should reference the twice-test, not route names.
