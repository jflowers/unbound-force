## ADDED Requirements

### Requirement: FR-001 Sync-Push Preview

The `/muti-mind.sync-push` command MUST display a preview of
what will be synced to GitHub before executing the push.

The preview MUST be generated by invoking
`go run cmd/mutimind/main.go sync-status` and presenting
the output to the user. The `sync-status` command always
reports on all backlog items (it does not accept an item
filter argument).

#### Scenario: Preview before sync (all items)

- **GIVEN** the user invokes `/muti-mind.sync-push` with or
  without an `[item_id]` argument
- **WHEN** the command begins execution
- **THEN** the command MUST invoke `sync-status` and display
  the sync state of all backlog items before any push occurs

#### Scenario: Preview step fails

- **GIVEN** the user invokes `/muti-mind.sync-push`
- **WHEN** `sync-status` returns an error or non-zero exit code
- **THEN** the command MUST display the error to the user
- **AND** the command MUST NOT proceed to the confirmation gate
- **AND** the command MUST NOT invoke the push backend

#### Scenario: Nothing to sync

- **GIVEN** the user invokes `/muti-mind.sync-push`
- **WHEN** `sync-status` reports no items requiring creation
  or update
- **THEN** the command MUST inform the user that there is
  nothing to sync
- **AND** the command MUST NOT present the confirmation gate

### Requirement: FR-002 Mandatory Confirmation Gate

The `/muti-mind.sync-push` command MUST present an
`AskUserQuestion` confirmation gate after the preview and
before invoking the Go backend push.

The confirmation MUST offer exactly two options:
- "Yes -- sync to GitHub"
- "No -- abort"

The push MUST NOT proceed unless the user selects "Yes".

#### Scenario: User confirms sync

- **GIVEN** the preview has been displayed
- **WHEN** the user selects "Yes -- sync to GitHub"
- **THEN** the command MUST invoke
  `go run cmd/mutimind/main.go sync-push [item_id]` and
  output the results

#### Scenario: User aborts sync

- **GIVEN** the preview has been displayed
- **WHEN** the user selects "No -- abort"
- **THEN** the command MUST NOT invoke the Go backend
- **AND** the command MUST display an abort message
  (e.g., "Sync aborted.")

#### Scenario: No bypass path

- **GIVEN** any invocation of `/muti-mind.sync-push`
- **WHEN** the command is executed
- **THEN** there MUST be no code path that invokes the Go
  backend push without first completing the confirmation gate

## MODIFIED Requirements

### Requirement: FR-003 Sync-Push Execution Flow

The `/muti-mind.sync-push` command instructions change from
a direct backend invocation to a three-step flow:
1. Preview (sync-status)
2. Confirm (AskUserQuestion)
3. Execute (sync-push backend, only if confirmed)

Previously: The command immediately invoked
`go run cmd/mutimind/main.go sync-push [item_id]` with no
intermediate steps.

## REMOVED Requirements

None.
